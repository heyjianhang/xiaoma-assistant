# 真实结果映射组件

先组合 `sql` 完成查询，再调用 `render_chart`；`result_id` 来自本轮执行返回的 `id`。只传视图和现有字段，不自行提交rows或补造数值。

| 视图 | 适用内容 | 参数约定 |
| --- | --- | --- |
| `metrics` | 一个观察范围的一行聚合指标 | `y_keys`选数值列；SQL用中文列名/别名，名称标单位 |
| `bar` | 类别数量、金额或比例比较 | `x_key`为分类，`y_keys`为同量纲数值，不混“合计”柱 |
| `line` | 日期趋势 | SQL按业务时区升序；`x_key`为日期，同量纲数值为`y_keys` |
| `table` | 业务明细、多列结果 | 展示现有字段，数值不拼接为带单位的字符串 |

- 标题说明统计对象与时间，查询条件与实际结果一致，不因出图重新改变口径。
- 每次渲染更新本轮同一结果视图；多指标尽量合并成一行查询后一次展示。确有多个结果时不要承诺会保留多个独立图表。
- 已要求出图且数据可用时实际调用工具，不用Markdown表格或“已生成”文字代替。工具会先显示自动查询表，再升级为所选组件。
- 结果为空先说明，不画有值的图；单个分母为0的比例保留NULL。截断结果不能当全量分布；必要时先重新聚合查询。
- 多单位指标可用指标卡/表格，不能把金额、笔数、比例强行放同一数量轴。不要将分类占比之和强行修成100%，先核对是否有交叉。
- 卡片后只补充关键发现、范围和限制，避免把同一结果全文复写一次。

无支付记录的日期按用户要求补0，解释为“本库在该查询范围没有匹配支付记录”。仅凭最后一笔支付时间，不能断言后续日期漏采集或改写观察期间；数据缺口需有明确的覆盖/完整性依据。
