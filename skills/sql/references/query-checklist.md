# 查询核对清单

## 粒度和关联

- 先从真实表说明确认主外键。订单数、退款单数、退款件数与退款金额不是同一个指标。
- 同单多次部分退款可合法存在；订单率按订单去重，退款品类沿实际退款行关联原购买行，不因混合订单的其他品类退款而扩大分子。
- 订单头金额在订单层求和；商品金额用历史购买行实付，不能用当前售价；退款行金额不能随多重关联重复累计。

## 时间和范围

- 未限定日期就保留全量；明确月份用带时区的左闭右开边界。相对日期读取演示上下文。正文直接使用已执行的起止日期并注明含/不含，不从下月1日拼出“0日”；需要月末时由日期运算取得真实日期。
- 按支付队列统计的退款与按退款到账月份统计的退款不同；保留订单支付窗口和成功退款截止两个条件。
- 业务规则从文档获取；当前订单状态不一定等同于历史观察截止前状态，查询发货/完成等事件时检查其时刻。
- 缺验收时间的退款无法算验收后时长；缺失样本与完整样本单独计数。不能用申请、更新或发货时刻替代。

## 计算和展示

- 整数相除要转numeric；分母为0返回NULL；零记录时COUNT可为0，SUM可能为NULL，按业务意义区分。支付分母为0时若需确认数据覆盖，可在同一范围核对原始记录数与未支付数，区分“无支付”和“无任何记录”；不要遍历其他地区或品类来替代这个核对。
- 退款率同时展示分子分母，按文档约定提示小样本；聚合比率先汇总分子分母，不平均百分比。
- 折线按真实业务日期与时区升序。需要补零日期时，在只读SQL中构造日期序列或VALUES/递归CTE，仍须引用已链接业务表；未发生的计数可补0，未定义比例/均值不能补0。
- 分类图不要混入“合计”行；排名指定前N名时排序后LIMIT N，不把其余类别加入主图。可另查总数在正文核验。跨品类订单有交叉时重新去重，而不是直接加分类订单数。
- 禁止任意外部函数、系统表和外部数据源。执行错误先看工具返回并修改；只读权限、字段授权和行数限制由服务端强制执行。
