# 渐进取结构，执行后给结论

## 1. 明确本次查询

保留用户指定的对象、时间、地区、范围与粒度。不限制日期的全量问题不要自行改成支付订单或月度范围。相对日期先按目录查演示参考时间表，不使用服务器今天替代。

退款率、客单价、到账时效等业务指标，优先组合 `knowledge` 核对定义、时间边界和缺失处理。用户已完整指定算法时按该算法查询并明确命名；定义仍含关键歧义时用 `ask_clarification`，不擅自替换。文档查询关闭时，区分可查原始记录和无法确认的规则，不能声称已经核对制度。

## 2. 显式Schema Linking

按依赖顺序执行：

`list_tables` 精简目录 → `get_table_schema` 每次1–3张候选表 → `link_schema` → 直接生成SQL并交给 `execute_readonly_sql`。

- 从目录选择候选，不猜字段，不把所有表结构逐一搬进上下文。已有本轮结构可复用，不重复查询目录。
- `link_schema.question` 写清查询目的和过滤范围；`tables` 仅选需要的列，也包括关联、筛选、分组列；`joins` 记实际关联；`grain` 记统计单位、去重与汇总方式。
- 需要新增字段或更改统计目的时先补看结构并重新链接。`context_id` 必须是本轮返回的；不能复用历史运行的ID。

## 3. 计算并核验

- 使用看到的字段说明与检索到的口径，区分订单头、购买行、退款头和退款行。先在各自粒度聚合再关联，防止订单金额被明细重复累计。
- 比例给出分子、分母、去重键；分母为0用 `NULLIF` 保留NULL，不格式化成0%。确认是否允许跨分组相加，不能直接平均比例。无合格样本时说明本范围没有匹配记录即可；若确需区分无支付与缺记录，只在相同范围核对原始记录，不主动遍历其他地区、品类或月份来证明数据完整。
- 时间起点、截止、成功状态和品类快照都按定义；缺关键时间保留NULL，不用其他时间补算。统计期间、观察截止与政策适用日期不要混为一谈。回答沿用SQL实际使用的合法日期，左闭右开区间写“起点（含）至下期起点（不含）”；不靠日期字符串减1生成月末，更不能出现0日或不存在的日期。
- SQL是单条PostgreSQL SELECT，可含CTE；显式列名，不用 `SELECT *`（`COUNT(*)`可用）。中文展示列可用双引号别名；数值保持数值类型，金额单位、百分比量纲写清。
- 本轮成功执行后才报告数值。空行、NULL、0、截断与失败分别说明；没有某日记录只能说明本库该日没有匹配记录，不能仅凭最晚一条记录的日期断言后续数据未覆盖或把用户的整月范围改成半月；有明确完整性标记才判断缺采集。200行是返回上限，不是全量样本数。需要排名或汇总时在SQL内完成，不能只对被截断的展示行下结论。用户指定前N名时，主结果在SQL中排序并LIMIT N，最终表格/图也只展示这N项；辅助全量核验不能覆盖主结果范围。
- 字段/类型/聚合错误按报错修改；没有完成查询就报告失败和已确认部分，不编造结果，不原样空转重试。

## 4. 回答与展示

自然语言先回答核心结果，再说明必要范围与限制。不要因为召回了月报等旁支资料就扩大查询任务；已有证据顺带发现差异可说明，但原因未知不反复试算。需要图表时加载 `visualize` 并使用本轮结果 `id`；需要对照文档时加载 `evidence-review`。SQL本身和任务清单不能代替答案。

涉及多表金额、退款率、趋势、时效或查询失败时，按需读取 [查询核对清单](references/query-checklist.md)。

多次SQL有主查询与辅助核验时，最终数据视图应对应用户要看的主结果。辅助查询使自动表格切换后，可组合 `visualize`，用主结果id调用 `render_chart(view="table")` 恢复主展示；正文不要只留核验明细。
