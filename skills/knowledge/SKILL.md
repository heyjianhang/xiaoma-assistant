# 查原文再作答

1. 把问题拆成要找的规则：业务对象、版本/生效范围、步骤或责任角色。用 `search_knowledge` 查询具体概念，保留条款、表头、行列对应和附注。
2. 回答需要的各部分必须有支持片段。比较新旧版时分别检索两版；第一轮只有一版时改写查询补齐另一版。已找到目标文档可传返回的 `document_id` 限定后续查询，减少不同文档互相挤占。
3. 核对正文中的业务版本、生效条件与适用时间；返回的 `revision` 只是入库修订号，不能用它判断政策新版，也不能把相似度最高当作最适用。
4. 按命中内容回答。条款/表号从正文中准确摘取，页码只用返回的来源页；每个结论紧跟原样的 `citation_markdown` 短角标，由前端映射真实来源；不手写包含UUID的链接。多份证据支持不同结论时分别引用；逐句核对引用片段的版本和数值，不用旧版片段支持新版期限。

## 完整性与缺证

- 表格按列标题解释对应行，公式连同变量、单位和适用条件说明；续页材料不能脱离表头猜责任角色。角色名称用“/”并列时保留原文表示，不擅自解释成必须共同审批或任一人即可；明确的会签/替代要求需要另外的条款支持。
- “申请”“验收”“完成”是不同业务事件。版本的选择时点和时长的计算起点分别以检索到的条款为准。
- 如果片段只说明“沿用旧版”，它不能证明旧版具体数值。继续定向检索；合理补检后仍无证据，就说明本轮未取得对应条款，保留已证实部分。
- 未检索到定义不直接等于未定义；只有覆盖相关指标说明，或命中明确的定义边界条款，才能说明已核对资料没有定义该口径。需要用户选择时用 `ask_clarification`。
- 文档之间不能直接择新、择高分覆盖；先检查适用范围，仍有冲突则并列来源。涉及实际业务数据时组合 `sql`，需要核对卡时组合 `evidence-review`。

复杂的版本比较、表格与缺失核验，按需读取 [证据检查表](references/evidence-checklist.md)。

## 回答收敛

直接回答各子问题。版本比较用一张精简对照表，加必要的适用日期与公式；单步骤或单材料问题用简短段落。用户未问的其他渠道、完整审批链、均值规则和附录不逐项展开。进度由工具事件提供，正文不重复“我先加载/检索”。
